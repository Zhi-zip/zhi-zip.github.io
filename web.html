Zhi-Zip Web 是在线压缩 / 解压服务：Flask 负责页面，FastAPI 提供接口， Celery + Redis 承担异步任务。上传即返回任务 ID，进度实时可见，产物一键下载。

Features

为 Web 场景重新设计的压缩内核

不止是把桌面逻辑搬到浏览器，而是在多用户、长任务、大文件的前提下重新划分职责边界。

多文件递归压缩

保留相对目录结构，解压后层次与原目录完全一致，不会出现文件平铺混乱。

防覆盖 + 防穿越

重名文件自动追加序号；解压前用 Path.relative_to() 逐项校验，杜绝 Zip Slip。

异步 + 实时进度

Celery 任务化，上传即返回 task_id；前端 800ms 轮询，进度条实时刷新。

框架完全解耦

压缩逻辑集中在 app/core/，Flask 与 FastAPI 都不直接调用 zipfile。

Windows 原生可用

Worker 使用 --pool=solo，配合 Memurai 无需 WSL / Docker 即可跑通全链路。

自带 Swagger

访问 :8000/docs 即可在线调试全部接口，无需额外装 Postman。

Architecture

四层分离，各司其职

浏览器只和 Flask 页面交互；页面通过 CORS 直连 FastAPI；耗时操作全部落到 Worker。

方法路径说明

        
        
          

            POST
            /api/compress/
            创建压缩任务，表单字段 files（可多个）、output_name
          

          

            POST
            /api/decompress/
            创建解压任务，表单字段 file，当前仅支持 .zip
          

          

            GET
            /api/tasks/{task_id}
            查询状态，返回 PENDING / PROGRESS / SUCCESS / FAILURE
          

          

            GET
            /api/download/{name}
            下载产物，限 storage/outputs/，路径已做穿越校验
          

        
      

    

  







  

    

      
FAQ

      
常见问题

    


    

      

        Worker 报 Error 10061 connecting to localhost:6379
        
Redis 未启动。Windows 上安装 Memurai 并设为服务，或使用 WSL2 / Docker 运行 Redis，确认 netstat -ano | findstr :6379 有 LISTENING 后重启 Worker。

      

      

        解压时报「不安全的路径」
        
请确认 app/core/safe_extract.py 使用的是 Path.relative_to()，而不是字符串前缀比较——Windows 的路径分隔符为 \，字符串比较会误判。

      

      

        改了代码但任务行为没变
        
Celery Worker 不会热重载。修改 app/tasks/ 或 app/core/ 后，必须 Ctrl+C 并重新执行 python run_worker.py。FastAPI 已开 reload=True，无需手动重启。

      

      

        支持 .tar.gz / .7z 吗？
        
当前版本仅支持 .zip。扩展方式：在 safe_extract.py 中新增 safe_extract_tar()，并在 decompress.py 里按扩展名分发。欢迎提交 PR。
